# Skills criadas no Tutti — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O Natan descreve em texto o que quer; um agente do Tutti escreve a skill, testa num caso de exemplo e ajusta; o Natan marca quais agentes usam a skill, e ela passa a valer nos pedidos desses agentes.

**Architecture:** Skill = `SKILL.md` (frontmatter `name`/`description` + instruções), guardada no SQLite. Criar, testar e ajustar são execuções em modo consulta (só leitura) de um agente escolhido, sem ponto de restauração nem conversa. Na hora do pedido, agentes Claude CLI recebem as skills como plugin local do Agent SDK (carregamento sob demanda, sem tocar `~/.claude` nem o projeto); os outros (Codex, Antigravity, opencode CLI e API) recebem as skills dentro das instruções.

**Tech Stack:** Electron 45, React 19, TS, zustand, vitest, `node:sqlite`, zod 4, `@anthropic-ai/claude-agent-sdk` 0.3.314 (`plugins`, `skills`).

**Spec:** não há documento de design separado: o Natan pulou as perguntas ("só segue"). A seção **Design** abaixo é a especificação; as decisões nela são minhas e estão marcadas como tal.

## Design

1. **O que é uma skill.** `Skill { id: string; name: string; description: string; body: string; agentIds: string[]; updatedAt: number }`. `name` em kebab-case (`/^[a-z0-9]+(-[a-z0-9]+)*$/`, até 64), único entre as skills; `description` 1–300 caracteres (diz *quando* usar); `body` 1–20 000 caracteres. Só texto: sem scripts nem arquivos extras nesta versão (decisão minha — scripts exigiriam execução e um modelo de permissão novo).
2. **Criar.** O Natan escreve o pedido e escolhe **quem cria** (qualquer agente disponível do perfil ativo). O agente roda em modo consulta numa pasta vazia do app e responde com o `SKILL.md` dentro de um bloco ```` ```skill ````; o Tutti extrai, valida e mostra para edição.
3. **Testar.** O Natan escreve uma tarefa de exemplo e escolhe o agente que testa. Ele roda em modo consulta no projeto aberto (ou na pasta vazia, se não houver projeto), com a skill nas instruções, e a resposta aparece na tela.
4. **Ajustar.** Quem cria recebe a skill atual, a tarefa e a resposta do teste, e um comentário opcional do Natan. Sem comentário, ele mesmo avalia se a resposta seguiu a skill e corrige o que faltou. Devolve um `SKILL.md` novo. Esse é o "ajusta sozinho para funcionar melhor".
5. **Quem usa.** Na skill, o Natan marca agentes de qualquer perfil (lista agrupada por perfil). Agentes removidos são ignorados na hora do pedido.
6. **Na hora do pedido** (pedido direto e passos do Time, que passam por `RunService.execute`): Claude CLI → plugin local `tutti` em `<userData>/skill-plugins/<agentId>/` + `skills: ['tutti:<name>', …]`; demais → bloco "Skills" nas instruções com nome, descrição e corpo de cada uma. Consultas entre agentes (Radar/Lupa no meio do trabalho) não recebem skills (decisão minha: economia, igual ao contexto compartilhado).
7. **Custos.** Criar, testar e ajustar contam no painel de uso (run id `skill:<rascunho>`). Se o agente escolhido é por API paga, o botão mostra "(API paga — Provedor)" e o main recusa sem `confirmPaid: true`.
8. **Onde fica na interface.** Menu do 👥 ganha **Skills…**, que abre uma janela no mesmo estilo de "Configurar perfis…".

## Global Constraints

- Textos da interface em português do Brasil; erros de validação em português.
- Chaves de API nunca em arquivo, log, banco em texto claro ou env das CLIs (já garantido pelo opencode; nada aqui pode mudar isso).
- API paga só depois de clique explícito do Natan (`confirmPaid: true` no IPC).
- Criar/testar/ajustar sempre em `mode: 'consult'` (só leitura).
- Nada é escrito em `~/.claude`, `~/.codex`, `~/.config/opencode` nem no projeto do Natan.
- Testes com vitest; renderer com `afterEach(cleanup)` explícito.

## Review Focus

1. Resposta do agente sem bloco ```` ```skill ```` ou com frontmatter quebrado → erro claro "O agente não devolveu uma skill válida." e o rascunho anterior intacto (Task 2).
2. Dois `name` iguais, ou renomear uma skill para o nome de outra → recusado com `Já existe uma skill chamada "x".` (Task 2).
3. Agente marcado foi removido do perfil depois → pedido segue normal sem a skill, sem lançar (Task 4).
4. Skill editada entre dois pedidos do mesmo agente Claude → o plugin no disco é regravado (pasta limpa antes), sem sobrar skill desmarcada (Task 4).
5. Fechar a janela no meio de "Criar"/"Testar" → a execução é cancelada (sem uso pago órfão) (Task 3 e 5).
