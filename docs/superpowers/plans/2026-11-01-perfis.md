# Perfis de agentes e modo API — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sair do time fixo: o Natan cria perfis do zero (agentes com nome, prompt, CLI ou API, modelo e papéis), escolhe o perfil por projeto, e agentes por API rodam com a chave dele guardada no Keychain, sempre com confirmação quando há API paga.

**Architecture:** O time fixo de `src/shared/agents.ts` vira o perfil "Padrão" (constante, só leitura); perfis do Natan ficam no SQLite. Um registro de agentes (`registerAgents`/`getAgent`) resolve qualquer id de qualquer perfil, inclusive de conversas antigas. Agente por API roda no servidor do opencode que o app já sobe, com as chaves passadas só para esse processo via `OPENCODE_CONFIG_CONTENT`. Papéis que hoje estão fixos no código (Bússola coordena, Lupa revisa, Radar/Lupa podem ser consultados) passam a vir do perfil.

**Tech Stack:** Electron 45 (`safeStorage` para as chaves), React 19, zustand, zod 4.6.7, `node:sqlite`, vitest, Playwright `_electron`.

**Spec:** `docs/superpowers/specs/2026-11-01-custos-e-perfis-design.md` (§2, §3, §6, §8, §10, §11; Parte 1 — §4, §5, §7, §9 — já está na main)

## Global Constraints

- Perfil "Padrão": o time atual, tudo por CLI/assinatura. "Não pode ser apagado **nem editado**; pode ser duplicado para servir de base."
- Anti-objetivo: chave de API "em arquivo do projeto, em log, no banco em texto puro ou no `env` de agentes CLI". Só o processo do opencode recebe a chave.
- Anti-objetivo: "Usar API paga **sem o Natan ter escolhido** explicitamente aquele agente/perfil em modo API. O perfil Padrão continua 100% assinatura."
- Trabalho só vai para agente por API paga (troca por limite ou escalação) "depois de confirmação explícita, com o aviso deixando claro que é pago".
- Escalação com agente por API paga: "o pedido passa a exigir aprovação do plano (como pedido grande), e o card do plano marca quais passos usam API paga. Recusar = nada roda."
- Política de comandos §6.4 vale para todo agente, em qualquer perfil e transporte (agente API = mesmas aprovações do Curinga).
- "Sessões só são retomadas se o agente continuar no mesmo transporte e modelo; trocar qualquer um dos dois começa sessão nova."
- Até 8 agentes por perfil. Modo API mostra só tokens (sem barra, sem dinheiro).
- Mascote = família do modelo: Claude → Clawd; GPT/Codex → nuvem; Gemini → estrela; demais → bloco do opencode; tom de cor varia entre agentes da mesma família.
- Coordenador opcional: sem coordenador, a aba Time some.
- Cada projeto lembra o último perfil usado; seletor de perfil no topo, ao lado do projeto.
- Textos da interface em português do Brasil, no tom atual ("Disponível", "Esperando você").

## Review Focus

1. **Trocar modelo ou transporte de um agente no meio de uma conversa** — o próximo pedido a ele começa sessão nova, nunca retoma a anterior. → Task 4.
2. **Apagar o perfil que um projeto usa** — o projeto volta ao Padrão; conversas antigas com agentes desse perfil continuam abrindo, com nome do agente e "(removido)". → Tasks 2 e 3.
3. **Agente por API sem chave do provedor** (nunca salva ou removida depois) — aparece "Sem chave da OpenRouter" no palco, fica indisponível, e não quebra a triagem nem o painel. → Task 4.
4. **Chave nunca volta para a interface nem vaza para CLIs** — `providerKeys()` só devolve quais provedores têm chave; `safeEnv()` continua sem chaves; só o env do `opencode serve` leva a chave. → Task 3 e Task 4.
5. **Substituto por limite que é API paga** — o cartão diz "(API paga — OpenRouter)" antes de [Passar]; sem clicar, nada roda nele. → Task 5.
